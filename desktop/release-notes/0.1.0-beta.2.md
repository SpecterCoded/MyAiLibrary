# MyAiLibrary 0.1.0 Beta 2

This emergency beta fixes the blank black window that could appear immediately after installing `0.1.0-beta.1`.

## What was wrong

The first public release workflow built the frontend without the Firebase web configuration used by the sign-in experience. Firebase was initialized while the renderer modules were loading, so the resulting `auth/invalid-api-key` exception happened before React could draw the application.

The packaged backend, local data directory, and frontend files were intact. The failure was limited to renderer startup and did not delete or corrupt user data.

## What changed

- Firebase authentication and Firestore now initialize lazily, only when an authentication operation needs them.
- A missing Firebase configuration can no longer prevent the desktop interface from rendering.
- Custom builds without Firebase values show a clear error inside the existing authentication screen when an auth action is attempted.
- GitHub Actions now supplies all required Firebase web configuration values to both beta and future stable Windows builds.
- The release workflow validates those values before tests and packaging. A misconfigured workflow now fails instead of publishing a black-screen installer.

## Verification

The production frontend was built and exercised with all Firebase values deliberately removed. The full sign-in interface rendered successfully, and an attempted sign-in produced the expected in-app configuration message instead of a renderer crash. The configured production build and frontend stream tests also pass.

## Installing this correction

`0.1.0-beta.1` users whose interface is blank should download and run the `0.1.0-beta.2` installer manually from this release. The installer upgrades the application in place and preserves the existing MyAiLibrary data directory.

The package remains an intentionally unsigned public Windows beta, so Windows SmartScreen may show the expected **Unknown Publisher** warning.
